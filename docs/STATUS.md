## 4. 单篇真实案例意味着什么

案例：[Multi-Head Low-Rank Attention](https://openreview.net/forum?id=vBJKZ19XGY)，本地论文 ID `33089`，持久任务 ID `599c14be781f4eac98fa5093dd7eea43`。

- 完整目标稿件约 88,275 字符，文本代理 token 27,319；检查与所有 1,286 篇规则来源的隔离。
- 24 条候选逐条判断：3 条适用、20 条不适用、1 条证据不足；加载 R6574、R8311、R1054，共 1,605 代理 token。
- 已生成 Review 与修改优先级，保留一个配置可比性的 P2 待核实问题；评分 6/10、置信度 2/5 是模型输出。
- 2 条 strength 和 1 条 concern 的引文已逐字核验；另一个不受支持的 strength 单独隔离，没有作为已核实意见展示。
- 第 2 次执行复用已有成功模型响应，完成本地恢复；该恢复没有新增付费调用。

此案例验证规则选择、来源排除、审稿响应、证据定位和恢复的工程链条。审稿准确性与改进幅度按下一节的独立评测协议验收。Skill 库页另保留 100 篇开发实验中的 5 篇旧库回放。

## 5. 后续顺序与验收条件

### 近期：稳定演示与迁移

1. 网站数据、规则与配对来源、案例三份演示包已建立文件清单与 SHA-256，见 [下载入口](DEMO_ASSETS.md)。
2. 部署与研究存储路径改用环境变量；提供安装、账号初始化与启动命令。地图与案例使用预生成快照，上传新稿使用随包规则。
3. 干净环境安装、地图、回放、自填接口与失败恢复的实测记录见 [部署验证](DEPLOYMENT_VERIFICATION.md)。
4. 继续记录真实使用的耗时、token、失败率与兼容接口表现。

### 研究：评测规则与审稿有效性

1. 清点所有已用于提炼、方案比较与调参的论文，重新确认开发/校准/留出边界。根据现有跨年开发样本重新冻结留出集。
2. 对未参与提炼的完整新稿，人工区分真实缺陷、待核实问题、建议和误报，检查引文是否真正支持 concern。
3. 比较“同模型无 Skill”和“按稿组合 Skill”，报告问题质量、有效覆盖、误报、成本和失败情况；预先固定评价规则。
4. 对实体提取、层次归属、规则适用性分别建立人工标注，不以字符命中率或 LLM 自评分代替准确性。

当前先完成单篇组合审查，正式质量评测作为独立后续工作。

### 后续扩展

其他领域规则库、多审稿人独立审查与 AC、在线作者响应、2027 趋势分析等，按明确的评测目标与预算逐项推进。进度按可运行实现及其验收证据记录。
