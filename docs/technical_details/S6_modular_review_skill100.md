# S6：AutoManual＋ACE 多级动态审稿 Skill

本轮固定为 100 篇历史论文凝练、5 篇未参与凝练的新稿试审。模型为
`gpt-6-luna`，思考强度 `medium`，API 并发最多 3；完成后等待结果检查，不自动扩展全量。
无训练、无对照、不处理 rebuttal。

## 数据与方法

复用 S4 已封存的 12,964 篇实体／核心内容结果及 BGE-M3 核心向量。候选池为生成模型、
强化学习、基础模型、安全对齐、学习理论，每领域选 20 篇历史论文。优先取 2024、2025
各 10 篇；基础模型没有 2024 年对应记录，取 2025 年 20 篇。领域／年份内选择有差异的
样本。每领域另选 1 篇与历史组接近的 2026 年论文试审。这是开发性展示，不是独立质量评测。

S4 一级标签用于分组，实体用于方法／任务检索；不把实体抽取结果当作已经验证的三级分类。
按 paper ID 读取 S4 文件，避免反复加载数百 MB 的汇总 JSON。原 S4 数据与数据库保持只读。

AutoManual 适配：每篇一次调用，从初始 Review 与正文片段归纳至多 5 条原子观察和
3 条候选检查项。规则保存适用条件、检查步骤、问题成立与消除条件、影响、例外及来源。
历史观点和个人偏好不是已验证事实；原文位置正确也不意味着审稿判断正确。

ACE 适配：100 篇抽取后，分为固定的 10 批，每批各领域 2 篇。串行读取相关已有规则并提出
至多 8 项局部操作：新增、细化、合并、拆分、停用。程序保存稳定 ID、旧／新内容、理由、
来源和版本哈希。没有被处理的候选保留。此处借鉴条目与增量机制，不复现完整多 agent 框架。

至少两篇独立论文的 Review—正文配对来源才能标记 `source_supported`；通用规则还需跨领域
来源。`candidate` 与 `deprecated` 单独保留。这个来源门槛不证明专家共识或科学正确性。

## 动态组合与试审

规则库冻结后，按一级领域、实体范围与来源向量选择至多 10 条规则，组合通用、领域、方法、
任务与专属模块。同一规则去重，模型在实际审稿时仍须检查适用条件。

为 100 篇来源和 5 篇新稿保存本地组合清单；来源稿上的组合只用于展示，不充当泛化效果。
五篇新稿各一次审稿调用，只输入当前稿件文本证据与组合规则。目标人类 Review、评分、decision
和作者回复不进入输入；试审结果不能直接修改共享规则。证据不足形成待调查记录。

正文为日期未核实的当前快照；初审为最早已观测版本，并在作者首次回复时间存在时要求早于它。
只读取回复时间元数据。输入是部分文本，图表和外部文献未核验；置信度最高 3/5。

入口：[modular_review_skill.py](../../scripts/modular_review_skill.py)。


也支持单独运行 `extract`、`curate`、`compose`、`review`、`report`。输入、协议与请求哈希
匹配时复用结果。并发阶段只写独立案例／审稿文件，规则版本串行更新。文件锁阻止同目录重复运行。
协议变化需新目录；不能混用不同提示词或模型的缓存。

正常为 115 次模型调用。每请求最多两次尝试，只对暂时性网络错误、429、5xx 自动重试。
认证或端点拒绝停止提交；结构校验失败保留原始响应，不自动产生修复调用。
输入代理 token 上限分别为抽取 8,000、整理 12,000、试审 10,000；输出分别为 2,500、4,500、2,500。
去除完整证据块以适配预算，原始快照保留，实际输入记录在请求中。

本次整理阶段做过一次显式上下文投影修正：只从整理输入移除重复观察与引用 ID 列表，
完整候选和案例证据保持保存。修正前 manifest、抽取代码及变更记录在 `runtime/`，
100 个抽取请求哈希在禁止网络调用的检查中全部匹配，没有重新抽取。

本地恢复记录保留在相应请求目录的 `recovery.json`。来源稿 21293、19234 各引用 4 个
有效正文片段，超过原结构的 3 个上限；仅将来源引用数量上限放宽至 8，保持所有引用和
其他约束不变。目标稿 23305 的 `T0014` 唯一对应已提供的 `T23305:P0014`，仅规范化该 ID，
原结构约束不变。三份原始失败尝试与原始响应均保留；没有补充证据或改写科学判断。

目录内提供 `REPORT.md`、`CASES.md`、`MODULES.md`、`CHANGES.md`、`AUDIT.json`、`summary.json`、`PROGRESS.md`、`manifest.json`、`cases/`、
`rule_library.json`、`registry.json`、`skills/`、`updates.json`、`versions/`、`compositions/`、
`reviews/` 和 `requests/`。用量来自 provider 返回；思考 token 是输出的子集。无用量返回的请求费用未知。

## 核验

离线测试覆盖独立论文计数、目标引用隔离、增量回放、并发上限、缓存幂等与失败停止。
运行后审计覆盖 105 篇正文／S4 哈希和字符位置、100 篇案例引用、10 次版本重放、组合去重、
5 篇试审输入隔离、实际模型／思考强度、请求并发及用量台账。
这些检查验证执行与可追溯性，科学准确性仍待检查。
