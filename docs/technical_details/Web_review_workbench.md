## 2. 页面与交互

**专家库。** 用“领域 × 专家层级 × 审查机制”的数量矩阵提供全局入口。
点击单元格筛选，结合关键词、来源状态检索全部模块，每页 30 个。
打开模块可核对审查对象、适用条件、潜在失效机制、步骤、问题成立条件、消除证据、影响、例外及来源论文。
默认浏览来源支持模块，候选模块单独选择；来源论文链接可返回原有地图并打开论文详情。

**稿件匹配预览。** 接受粘贴文本或本地 TXT/Markdown/LaTeX 文件，不上传文件、不调用模型、不写浏览器持久存储。
五步路径为“稿件 → 声明领域及词面线索 → 推荐模块 → 待检查项 → 尚未执行审稿”。
按完整 scope 短语和 scope 词 IDF 检索，最多推荐 6 个模块、10 条规则；先保证每个模块至少展示一条，再补充第二条。
完整短语附输入原文片段和零起点字符位置；词面得分不解释成领域概率或审稿置信度。
候选默认排除，可显式启用；明确声明其他领域时不自动应用 LLM 库。
领域未知时只显示“LLM 库内匹配，待确认”，不生成虚构领域分布。
无匹配时允许空结果，历史检查项不自动成为新稿的缺陷。
输入上限 200,000 字符，超限明确拒绝、不截断；文件读取上限 2 MB。
PDF 解析、语义路由和实际审稿留给后续后端。

**已有审稿回放。** 采用 `modular_skill100_automanual_ace_v1` 的 5 篇真实试审：
32064、40652、36957、33499、23305，共 8 条 concern，其中一篇没有 concern。
显示原始领域、旧库名称与内容哈希、实际加载模块／规则、路由理由、适用性记录、原始 concern、影响、修改要求及逐条正文证据。
回放原始输出不改写。每次审稿当时为一次模型调用组合执行，不伪装为多个专家独立发言。
历史运行只输入部分文本，置信度低、图表和外部文献未核验，这些范围跟随运行记录展示。
这些记录不是最新 llm-area-v1 的试审结果；同名规则 ID 按各自的库哈希解释。

## 3. 数据与工程

- [export_reviewers.py](../../web/export_reviewers.py) 只读冻结发布包与旧试审记录。先核对发布清单哈希、注册表与规则文件哈希、规则库内容哈希，再核对每条有效规则唯一归属。
- 规则每 100 条分片，页面只按需加载模块详情。索引约 2.4 MB，沿用网站静态 JSON 分发方式。
- 回放引用核对原稿字符区间，要求 concern 引用存在且对应当次实际加载规则。历史库与当前库分开保存。
- [reviewers.html](../../web/reviewers.html) 与 [reviewers.js](../../web/reviewers.js) 使用原生 DOM、SVG、CSS；[review-match.js](../../web/review-match.js) 做浏览器词面检索，没有新增依赖或后端。
- Vite 采用两个 HTML 入口；更新主站入口及来源论文参数 `?paper=<paper_id>`。地图的数据与数学布局保持原流程。
- 新稿文本通过 `textContent` 显示，避免把输入当作 HTML 执行。

## 4. 复现与验收

在仓库根目录先导出：

```bash
PYTHONPYCACHEPREFIX=/tmp/iclr-review-workbench python3 web/export_reviewers.py
```

随后在 `web/` 下执行：

```bash
npm run reviewers:check
npm run build
npm run reviewers:smoke
```

已有 Linux 无头 Chromium 可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定；
`ICLR_WEB_BASE_URL` 可将同一浏览器验收指向局域网入口。

验收覆盖冻结身份与归属、关键词／状态／层级筛选、矩阵键盘操作、分页、文件读取、
默认排除候选、无匹配与范围外稿件、输入 HTML 转义、5 篇回放的 8 条原始 concern、
证据文本逐字一致、来源论文详情跳转及窄屏布局。匹配和回放都不产生上传或模型请求。
记录位于 `docs/research/web-review-workbench/`，截图位于被 Git 忽略的 `web/artifacts/`。
