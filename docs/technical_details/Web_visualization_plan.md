## 2. 固定架构与交互目标

```text
现有 PostgreSQL 与对象存储
    ↓ 只读提取、版本化派生数据
统一 Web 数据接口
    ├─ 论文列表、搜索与详情
    ├─ 向量、固定二维坐标与地图元数据 → Embedding Atlas
    ├─ 超边及成员关系 → HINTs / 独立超图组件
    └─ 审稿统计与分组数据 → R + ggdist → SVG
    ↓
自己的 Web 页面：共享筛选状态、选中论文集合和详情面板
```

典型流程：用户在地图上框选论文 → 超图展示这些论文共享的主题、方法或数据集 → 审稿面板展示同一论文集合的评分分布与分歧 → 点击论文查看原始审稿、回复和决定。

所有视图以 `paper_id` 关联；OpenReview `forum_id` 用于来源定位。统一筛选契约至少包括年份、主题、决定状态、评分口径、选中论文集合，以及数据、投影和分类版本。评分缺失、决定未知与明确拒稿分别处理。

## 3. 六步实施路线

每一步通过验收后再更新状态。阶段交付物中的文件名、接口名和实现位置可以按现有服务调整，但数据口径与验收要求保持一致。

| 步骤 | 目标 | 核心交付物 | 当前状态 |
|---|---|---|---|
| V1 | 数据契约与接入验证 | 字段字典、技术栈确认、三个工具的接入结论 | 已完成；[验证记录](Web_visualization_V1.md) |
| V2 | 生成地图数据 | 可复现的向量、二维坐标、论文元数据快照 | 部分交付：12,964 篇已有 S4 BGE-M3 向量与固定投影；统一数据库登记待完成 |

| V4 | 审稿统计面板 | 统一口径的统计接口、ggdist SVG | 部分交付：S4 全队列 ggdist、领域/标签/共现交集评分与录用统计；分歧/区间待完成 |

### V1：固定数据契约，验证工具接入

工作内容：

1. 确认现有 Web 服务的框架、代码位置、接口约定和部署方式；若尚无服务，再选择最小可运行技术栈。
2. 清点论文、题目摘要版本、主题、决定、评分和历史修订覆盖率，记录数据快照时间。
3. 明确地图每篇论文使用的文本版本；明确评分分析默认选择的审稿版本，并记录跨年量表定义。
4. 用少量真实论文验证 Atlas 组件嵌入及选中事件；验证 R/ggdist 到 SVG 的渲染路径。
5. 定位 HINTs 官方来源，核实许可证、维护状态、输入格式、布局、嵌入方式与选择事件。如果不适合直接复用，记录原因并选择符合许可证的独立实现路径，保留超图探索目标。

交付物：数据字典、共享筛选状态说明、工具版本与许可证清单、最小接入验证记录。

验收：真实论文可通过统一标识贯通数据与试验组件；三个工具均有明确接入结论；未知字段、缺失值和版本规则有记录。HINTs 的待核实项不阻止 V2–V4 的独立工作。

### V2：准备向量、固定坐标与地图元数据

工作内容：

1. 首版使用标题与摘要生成论文向量；输入不混入评分、审稿意见或决定。
2. 选择一个向量模型和一套输入模板，先做分层小样本检查，再生成全量数据；记录模型版本、文本版本、内容哈希、维度与失败状态。
3. 将各年份论文放在共同向量空间中，生成一套固定二维投影，记录算法参数、随机种子和投影版本。普通筛选只隐藏或显示点，不重新布局。
4. 关联年份、显式主题、关键词、决定状态及明确口径的评分摘要；保留元数据来源。
5. 向量按既有 `semantic.embedding` 契约写入；坐标与导出数据的存储位置在 V1 确认后固定，支持断点续跑。

交付物：向量生成任务、版本化地图数据集、覆盖率与失败报告。

验收：全量论文均有成功或失败/缺失状态，重跑可复用未变化输入；跨年模型一致；筛选前后同一论文坐标不变；地图元数据不会因一对多关联重复计算论文。二维邻近用于浏览，精确语义近邻使用原始向量。

### V3：接入语义地图和论文详情

工作内容：

1. 在自己的 Web 页面中嵌入 Atlas，加载 V2 地图快照。
2. 支持缩放、悬停、框选，以及按年份、主题、决定状态筛选和着色。
3. 提供标题/关键词搜索；语义检索使用与数据一致的查询向量模型和原始向量近邻。
4. 点击论文展示标题、摘要、关键词、OpenReview 链接、评分概览、审稿及讨论入口。
5. 建立共享筛选状态和选中论文集合，为 V4/V5 接入保留统一接口。

交付物：可在本地服务打开的地图与详情页、论文查询和地图数据接口、运行说明。

验收：从地图选点、搜索或列表均能定位同一篇真实论文；筛选计数与数据库口径一致；详情可追溯来源；无向量或无评分论文得到明确展示。

阶段价值：此时交付第一版可独立使用的论文浏览工具。

### V4：接入 ggdist 审稿统计

工作内容：

1. 对每条审稿只选择一个符合当前口径的版本，防止修订记录被当成独立样本。
2. 首批提供：按年份/主题/决定分组的评分分布、论文内评分分歧、评分与审稿人自报 confidence 的关系。
3. 分歧指标采用明确标注的评分极差、标准差等描述量，展示有效审稿数；审稿不足的论文单独标记。
4. 离散评分优先采用点图或直方图；半眼图、区间图用于合适的分布或估计量，区分观测分布、置信区间与可信区间。审稿人自报 confidence 保留为原始字段。
5. 跨年比较先核对量表，默认分年展示；需要统一变换时保留原值并公开规则。估计分组差异的区间时考虑同一论文内多条审稿的相关性，例如按论文分组 bootstrap。
6. 由 R/ggdist 输出 SVG，先服务预设分组，再接入选中论文集合；按数据版本、筛选条件和统计参数缓存结果。
7. 改分分析只纳入可验证的历史版本，标注覆盖率、时间点与配对规则；完整覆盖不足时仍可交付静态分布分析。

交付物：统计口径文档、统计接口、R 绘图脚本、可嵌入与导出的 SVG。

验收：地图选区与统计面板的论文集合一致；样本数、缺失值、版本和区间含义可见；聚合结果能用 SQL/独立计算复核；空集合和少样本返回可解释结果。

阶段价值：完成“语义地图 + 论文详情 + 审稿统计”的核心 MVP。

### V5：接入 HINTs 局部超图

工作内容：

1. 固定首版含义：论文作为节点，共享同一主题或关键词的论文构成一条超边；后续扩展至任务、方法和数据集。
2. 定义超边记录与成员关系，至少保存类型、标签、来源、版本，以及每项成员归属的证据；模型抽取结果另保留模型、置信信息和证据位置。
3. 根据 V1 结论复用 HINTs 或实现独立组件，通过适配器接收统一超边数据。
4. 只加载当前选区、检索结果或指定主题的局部超图，支持按超边类型、规模和证据来源过滤。
5. 点击超边查看成员论文，点击论文打开共用详情面板；显式主题、关键词与模型抽取标签可区分。
6. 根据实际测试确定节点/超边上限。超过上限时明确提示范围，并提供缩小筛选或聚合方式，不静默丢弃数据。

交付物：超边与成员数据契约、构建任务、查询接口、超图组件与来源查看功能。

验收：每条超边可查询真实成员与归属依据；显示范围和截断状态明确；多成员集合语义得到保留；局部图操作不改变地图投影。

### V6：统一联动、验证性能与完成部署准备

工作内容：

1. 打通地图选区 → 超图 → 审稿统计，以及超边选择 → 地图高亮/筛选 → 审稿统计；详情面板复用同一论文标识。
2. 区分全局筛选、当前论文集合、悬停与临时高亮；支持清空选择、返回上一步，并让可复现的筛选条件可分享。
3. 处理连续筛选请求，取消或忽略过期响应，避免三个视图显示不同批次的数据。
4. 基于全量地图和代表性选区测试首屏加载、筛选、局部超图和 SVG 渲染；记录测试机器、浏览器、数据规模与耗时，再据实确定缓存、分页和聚合参数。
5. 在可控样本和全量快照上检查论文集合一致性、计数、边界值、无结果、缺失值和服务失败时的页面行为。
6. 提供安装启动、数据刷新、缓存失效、版本追溯和部署说明；交付可审阅的运行版本与验证报告。

交付物：联动 Web 服务、功能与性能验证记录、数据刷新和部署文档。

验收：同一筛选条件下三个视图的论文集合一致；统计和图关系可追溯；保存的筛选可恢复；服务可按文档在目标环境启动。正式对外部署按后续明确的部署范围执行。

## 4. 迭代顺序与范围

- 默认实施顺序：`V1 → V2 → V3 → V4 → V5 → V6`。
- 第一个可用里程碑：V3，论文语义浏览与详情。
- 核心 MVP：V4，增加审稿统计。
- 完整探索版：V6，地图、超图和审稿分析联动。
- 首版复用 Atlas 渲染组件；ggdist 使用服务端 SVG；超图从显式主题和关键词开始，不等待完整模型标签。
- 新分类、方法/数据集标签和审稿轨迹按版本逐步接入。展示历史快照或正式测试集的工具标签需要清楚；浏览反馈若被用于后续模型调参，按总体计划重新记录数据用途。
- 当前 reviewer 标识按论文隔离，因此首版提供论文内审稿分歧与群体统计，不将其拼接为跨论文的个人行为轨迹。
